# 学不通公开源码与更新

项目地址：https://github.com/A3697/XueBuTong

原创融合代码使用 MIT；OCS 网课助手部分保留上游版权和许可。星蝉受保护运行时、原生前端、来源于其前端的页面源码不公开。GitHub Release 同时提供完整安装包与适用于前一兼容版本的增量包；完整包包含星蝉 1.3.1 运行组件，支持首次安装。私有账号、密钥、浏览器缓存、实例日志和登录凭据均不属于公开内容。

## 从 GitHub 更新

点击主窗口左上角图标，在说明页中点击“检查更新”。发现更新后先下载，再点击“退出并安装”。下载使用 HTTPS 直连 GitHub，校验 GitHub Release 提供的 SHA-256 摘要；不会沿用代理环境变量。正在运行或启动中的账号必须先停止。

程序内更新下载名称为 `XueBuTong-Update-版本-win-x64.exe` 的增量包。它不是首次安装包；需要更新星蝉组件时，可在经过独立清单审核后包含该组件差分，并在发布清单中注明。安装器核对本机版本、组件清单及程序文件；不兼容、组件缺失或本地程序文件已被修改时会停止。此时或首次安装请在 Release 下载 `XueBuTong-版本-win-x64-setup.exe` 完整包。用户数据不被覆盖。

更新前，原程序文件按本次实际替换或移除范围备份在安装目录的 `updates/backup-版本-时间` 中。安装过程中断后请先退出所有学不通进程，使用对应版本的完整安装包修复；需要从备份回退时，应同时按发布清单处理本次新增文件，不能只覆盖旧文件或混用其他版本备份。Inno Setup 保留并追加原卸载记录，仍可卸载原有全部程序文件。软件不会自动安装更新，不改动官方 OCS 脚本的独立更新管理。

## 公开工程的构建边界

公开仓库可修改原创 Node.js/Python/C#/C++ 模块以及许可明确的 OCS 应用代码。OCS 应用前端包含已编译的 Vue 资源，不能误称为完整上游 TypeScript 工程。

完整离线安装器仍需维护者本机配套的 `XueBuTong_构建依赖` 和未公开的星蝉页面资源。GitHub 仓库不包含这些组件，也不自动下载来源不明的副本；仅克隆仓库不能独立重建完整融合安装包。独立依赖的 LICENSE/NOTICE 必须保留。

增量包使用 `build/build_public_update.py` 构建，输入为已审核的当前程序目录及旧版发布清单。默认仍由 `build/public_scope.py` 限定为公开代码，拒绝非公开变更和文件删除。此公开源码边界不因完整包或组件增量包而扩大。

从 2.5.14 起，星蝉组件增量必须额外提供 `--star-runtime-delta` 和 `--candidate-manifest`。前者由 `build/star_runtime_delta.py` 从旧版、新版完整发布清单生成，维护者审阅后才作为构建输入；它绑定两份清单的 SHA-256、组件版本和逐文件旧新 SHA-256。允许的范围仅为 `star-runtime/` 和 `assets/star-native/`；用户数据目录、通配路径、其他非公开组件变化和清单外操作继续拒绝。

组件增量在编译前核对完整候选目录，沿用脱敏检查；安装时核对所有保留的星蝉程序文件及每一个替换/移除项，备份后仅按明确文件名移除失效资源，不继承完整安装器的其他清理规则。安装清单接受本次旧版或新版的对应哈希，便于重复安装及修复同一次中断。发布清单标注 `closedComponentsIncluded`、`starRuntimeDelta` 和 `removedFiles`，不能把包含受保护组件的包称为仅公开代码更新。

维护者可先用 `--prepare-only` 输出增量载荷、`installer.iss` 和 `update-plan.json`，不编译或执行安装器。审核清单生成和这一步检查均不等同于实际安装、升级及回退验收；交付前仍需分别验证完整包首次安装、增量升级、重复升级、不兼容基线拒绝和用户数据保留。

常用原创模块回归测试：

```powershell
node --test build/test_backend_lifecycle.cjs build/test_github_updates.cjs
python -B build/test_native_backend_mode.py
```

上述自动测试不涉及真实账号或课程提交。完整 UI、课程任务、第三方服务额度和长时间运行必须另外验收，不能从单元测试通过推断全部功能已完成实际验证。
