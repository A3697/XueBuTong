# 源码与构建说明

本交付对应学不通 **2.5.13**，依赖 OCS 网课助手桌面底座 **2.9.24**、网页脚本 **5.4.2**、星蝉刷课 **1.3.1**。目录日期 `261123` 表示 2026-11-23。产品元数据以根目录 [fusion-install.json](../fusion-install.json) 为准。

## 源码、程序和依赖的关系

| 交付位置 | 重组到程序目录的位置 | 说明 |
|---|---|---|
| `src/fusion/` | `src/` | 融合层实际源码；Node.js 主进程、浏览器侧增强、Python 状态与策略适配共用当前版本。 |
| `src/backend-host/` | `tools/` | Python 后端宿主、启动凭据、路径及运行时校验等工具。 |
| `src/native-helpers/` | 源码不直接拷入程序；预编译文件由外置 `runtime/tools/` 提供 | 浏览器窗口守卫及 DLL hook 的 C++17 源码，供后续维护。 |
| `src/star-panel/` | `star-runtime/web/dist/` | 当前定制前端，不以新版原始页面覆盖已有融合交互。 |
| `src/ocs-app/` | `ocs-lab/resources/app/` | 修改后的 OCS 应用 JS 与编译页面；`node_modules` 从外置依赖恢复。 |
| `assets/` | `assets/` | 程序使用的图标、页面、说明图片及默认脚本。 |
| 根目录 `fusion-install.json` | `fusion-install.json` | 版本和依赖标识。 |

Electron 安装目录使用的 `xingchan-lab-bootstrap.cjs` 副本在构建时从融合层的统一源码恢复，源码交付中不保留第二份相同文件。不要分别修改两个运行副本。

`src/fusion`、`src/backend-host`、`src/star-panel`、`src/native-helpers` 和 `build/Launcher.cs` 保存可读的融合实现与窗口辅助程序源码。`src/ocs-app` 是当前应用随包 JS 和已编译 Vue 资源，不等于一份可重新执行上游完整 TypeScript/Vue 构建链的原始仓库。星蝉后端来自外置受保护运行时，未提供其解密源码。

## 执行构建

在 Windows x64 的 PowerShell 7 中进入源码目录：

```powershell
.\build.ps1
```

入口参数固定为：

| 参数 | 含义 | 默认位置 |
|---|---|---|
| `-DependencyRoot` | 外置依赖目录 | 同级 `XueBuTong_构建依赖` |
| `-WorkRoot` | 重组程序、审计结果和构建日志所在的新工作目录 | 同级 `XueBuTong_构建缓存/<源码目录名>-<时间>` |
| `-OutputRoot` | 安装包及构建结果输出目录 | 同级 `XueBuTong_发行包/2.5.13-20261123` |

指定目录示例：

```powershell
.\build.ps1 -DependencyRoot '..\XueBuTong_构建依赖' -WorkRoot '..\XueBuTong_构建缓存\2.5.13-clean' -OutputRoot '..\XueBuTong_发行包\2.5.13-20261123'
```

入口通过外置 `runtime/python3144/python.exe` 的隔离模式执行 `build/build.py`。它依次核对 [源码清单](../source-manifest.json)、依赖清单与 [程序输入清单](../build/release-input-manifest.json)，重组 `candidate`，生成发布元数据并运行脱敏/发布审计，最后调用 Inno Setup。路径和来源不符合固定清单时停止，不自动采用其它文件补齐。

`WorkRoot` 必须新建或为空；编译器不会覆盖 `OutputRoot` 中已有的同名安装包。安装器名称不带临时构建标记。构建结果与日志写入外部工作目录的 `build-result.json`、`build-log.jsonl`，安装包与对应构建 JSON 位于输出目录。应用安装与首次启动是后续独立操作，构建过程不修改已有安装。

## 当前构建链的范围

这是固定输入的基线重组与安装器编译流程，不是从上游原始源码重编译所有第三方组件的工程。预编译启动器的来源绑定记录在 [dependency-provenance.json](../build/dependency-provenance.json)；当前入口不会根据 `Launcher.cs` 的变化自动生成新 EXE。也不能据此重建星蝉加密业务模块。

### C++ 窗口辅助程序

`src/native-helpers/browser-window-guard.cpp` 管理本程序启动的浏览器窗口，`browser-window-hook.cpp` 实现关闭时隐藏窗口的配套 DLL。运行时 EXE 与 DLL 必须成对放在程序 `tools/` 中；公开源码目录不放这两个已编译文件。

当前离线构建只重组外置依赖中的预编译文件，不调用 C++ 编译器。修改辅助程序需要 Windows x64 的 MSVC C++17 工具链和 Windows SDK，链接 `user32.lib`、`comctl32.lib`、`shell32.lib`、`ole32.lib`、`propsys.lib`。沿用 2.5.6 已构建并验证的 v4 辅助程序，原构建使用 MSVC 工具版本 14.44.35207 与 Windows SDK 10.0.26100.0；这些编译工具不随包提供。可以单独运行 `build/build_native_helpers.ps1`，通过参数指定已有工具链和输出目录。

[dependency-provenance.json](../build/dependency-provenance.json) 的 `nativeHelpers` 记录对应源码与二进制 SHA-256；原生关闭输入、后台保活、姓名与分组由独立测试和真实浏览器复验。修改源码后应在独立工作目录编译与验证，再同时更新二进制、摘要和发布清单。

如果修改程序，先在新的版本工作副本中完成代码、必要的启动器重编译和验证，再更新版本元数据、实际依赖、来源绑定和相应清单。旧清单的哈希不再对应新代码时，不应修改校验逻辑让它跳过检查。新的源码目录、依赖记录和安装包必须描述同一版实际输入。

## 后续版本与增量恢复

分享目录命名为 `XueBuTong_v<版本>_<YYMMDD>`，版本来自产品元数据，日期取该轮源码建立日期，最终验证日期另记在回归报告。源码目录只保留当前使用的文件；构建缓存、安装包、旧程序、测试运行目录、分析工具和插件配置放在目录之外。

旧版恢复资料采用增量方式，放在分享目录外：

1. 先保存旧清单和新清单，按相对路径、大小及哈希比较新增、修改和删除项。
2. 只保存旧版中“被修改或被删除文件”的原始字节，并保持其相对路径；新增项只需记录路径及新哈希。
3. 记录来源版本、目标版本、前后哈希与恢复方向，校验备份字节可读且与旧哈希一致。
4. 校验新目录符合新清单、增量资料足以恢复旧清单后，才清理重复旧目录与明确失效的生成文件。

从新版回退时，先检查当前文件是否仍与目标清单一致；将新增文件按清单移出，恢复增量备份中的修改/删除项，再逐项核对旧清单。来源不明、哈希不符或恢复资料缺失的文件应先保留，不能仅凭文件名认定可删除。

账号、浏览器缓存和日志不属于源码增量备份。它们运行时才生成，是否保留由应用及卸载选项处理，不随分享源码提供默认账号数据。

## 应用中心目录

`src/ocs-app/public/application-catalog.json` 是 2026-10-30 从 OCS 官方公共接口 `https://cdn.ocsjs.com/api/ocs-app-infos.json` 取得的随包目录，不包含本机账号和启用状态。

应用中心先显示随包或已缓存目录，再后台刷新；原浏览器元数据使用者仍优先尝试在线获取。网络异常、10 秒请求超时或返回内容格式异常时保留完整目录，点击“刷新应用列表”可重试。安装、卸载及启用状态沿用原有实现。
